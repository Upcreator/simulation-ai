# LangGraph Character Chat — MVP симуляция

Прототип долгоживущей симуляции для ролевых сценариев, где **LLM не является
источником памяти**. Модель — это только рассуждение и генерация реплик;
всё, что должно пережить запрос (персонажи, правила, мир, история событий),
хранится снаружи, в markdown-файлах, и пересобирается заново на каждый вызов.

Оркестрация потока — на **LangGraph**: узлы графа отвечают за загрузку
контекста, вызов модели и запись новых событий в память. Мониторинг —
через **Langfuse**. Модель — через OpenAI-совместимый **прокси**.

> ⚠️ Это MVP-прототип, не production-билд. Задача — проверить архитектуру
> "внешнее состояние + stateless LLM", а не построить готовый продукт.

## Ключевой принцип

LLM — это stateless reasoning engine. Он не помнит ничего между вызовами.
Промпт на каждый запрос собирается заново из внешних данных:

```
Запрос пользователя
       │
       ▼
Загрузка markdown (skills, world, персонажи, хроника)
       │
       ▼
Сборка промпта (PromptBuilder)
       │
       ▼
Вызов LLM
       │
       ▼
Получение ответа
       │
       ▼
Запись структурированной записи в хронику (если накопилось достаточно реплик)
       │
       ▼
Ответ пользователю
```

## Персонажи (personas/)

Каждый персонаж — независимый markdown-файл. Никакой персонаж не зашит в
Python-код. Добавление нового персонажа = создание нового `.md`-файла (через
UI во вкладке «🌍 Мир и персонажи» или руками).

Карточка обычно содержит: роль, характер, стиль речи, предысторию — но
структура не жёсткая, можно писать что угодно, всё уходит в системный
промпт как есть. Первая строка `# Имя` становится отображаемым именем.

## Правила и мир (skills/)

- `skills/skill.md` — поведение системы: как персонажи должны отвечать,
  ограничения формата, общие для всей симуляции инструкции.
- `skills/world.md` — сеттинг: эпоха, атмосфера, правила мира. Общий фон,
  который подмешивается в промпт каждого персонажа.

Оба файла редактируются через UI и применяются сразу, без перезапуска.

## Память (memory/history.md)

**Единственная постоянная память всей симуляции** — не привязана к
конкретному персонажу или разговору. После того как в текущей сессии
(чат с персонажем или диалог двух персонажей) накапливается больше
`MAX_MESSAGES_BEFORE_SUMMARY` сообщений, старые реплики сжимаются моделью
в структурированную запись (заголовок / участники / суть / последствия) и
дописываются в конец `memory/history.md`. При каждом новом запросе вся
хроника целиком подгружается в промпт — так персонажи "помнят" события,
даже если сами в них не участвовали физически в этой сессии.

Это намеренно простое решение: MVP **не решает** проблему бесконечного
роста файла (см. Non-Goals в исходном видении проекта) — в будущем
`load_history()` можно заменить на `Retriever.search(...)`, не меняя графы,
которые её вызывают.

Хронику можно смотреть, редактировать и очищать вручную в UI —
например, чтобы вписать стартовые события перед началом симуляции.

## PromptBuilder (src/prompt_builder.py)

Единственная ответственность — собрать финальный системный промпт:

```
skill.md + world.md + memory/history.md + карточка(и) персонажа(ей) + доп. контекст узла
```

Никакой бизнес-логики внутри — только загрузка и конкатенация.

## LangGraph-графы

- **graph_chat.py** — `agent` (строит промпт через PromptBuilder, зовёт LLM)
  → `memory` (проверяет, не пора ли сжать историю в хронику).
- **graph_dialogue.py** — `speak` (по очереди говорит от лица одного из двух
  персонажей) → `memory` → цикл, пока не кончатся реплики (`turns_left`).

`SqliteSaver` в обоих графах хранит только **короткий рабочий хвост**
сообщений текущей сессии (per `thread_id`) — не источник истины для
долгосрочной памяти, это по-прежнему `memory/history.md`.

## Установка

```bash
git clone <твой-репозиторий>
cd langgraph-character-chat
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
# заполни .env своими ключами
python app.py
```

Открой http://localhost:7860

## Docker

```bash
docker build -t character-chat .
docker run -p 7860:7860 --env-file .env \
  -v $(pwd)/personas:/app/personas \
  -v $(pwd)/skills:/app/skills \
  -v $(pwd)/memory:/app/memory \
  -v $(pwd)/data:/app/data \
  character-chat
```

Все четыре volume-а важны: без них персонажи, правила, мир и хроника,
изменённые через UI, будут теряться при пересоздании контейнера.

## Известные ограничения прототипа

- Хроника — простой markdown-файл, без векторного поиска по фактам; при
  очень долгой симуляции она будет расти без ограничения (это осознанный
  компромисс MVP, см. раздел «Память» выше).
- Общая хроника означает, что события одного разговора становятся видны
  системе в целом — это часть замысла ("симуляция"), но если нужна
  строгая приватность между разными чатами, потребуется доработка
  (например, разделение хроники по "сценам"/"комнатам").
- В диалоге двух персонажей нет вмешательства пользователя посреди
  разговора — сначала выполняется весь диалог, потом можно почитать
  транскрипт.
